# Botとの連携仕様

XStoryLIFFとBot（XStoryBot）のやり取りをまとめます。Bot側では、シナリオに `##liff.<action>` という条件で応答を書きます。

## 1. 通信の形

画面は、XStoryBotのLIFFの取り決め（XStoryBotの[LIFFページとWebchatの連携仕様](https://github.com/alt-core/XStoryBot/blob/master/docs/liff-webchat-api.md)）に従って、actionを送ります。LINEとXStoryBotのWebchatのどちらで開いたかで、送り先が変わります。どちらも、同じシナリオ、同じ台本の読み方です。ページ側の実装は `src/lib/xstorybot.ts` にあります。

| 開き方 | 見分け方 | 送り先 |
|---|---|---|
| LINE（LIFF） | URLに `xsb_client` が無い | `<VITE_API_BASE_URL>/liff/<VITE_BOT>/message` へ、LIFFのアクセストークンを付けてPOST |
| XStoryBotのWebchat | URLに `xsb_client=webchat`（Webchatがページをiframeで開く時に付ける） | Webchatの画面（親）へ `postMessage` で送り、親がBotを実行する（protocol `xstorybot-liff`、version 1） |

LINEでは、次の形で送ります。

```http
POST /liff/story/message
Authorization: Bearer <LIFFのアクセストークン>
Content-Type: application/json

{"action": "get_status"}
```

XStoryBotは、アクセストークンからLINEのユーザーIDを確かめ、actionの先頭に `##liff.` を付けて、シナリオの条件として実行します。トークと同じ利用者として扱うので、フラグを共有できます。Webchatでは、会話のBot自身をLIFFの連携先にすると、同じように会話とフラグを共有できます（[公開手順](deployment.md#xstorybotのwebchatで使う)）。

XStoryBotの取り決めでは、同時に1つの操作しか受け付けません（重ねると `busy`）。画面は、Botへの送信を送る順に1つずつ送ります。

応答は、シナリオが返した行の配列をJSONの文字列にしたものを、`message` に包んだ形です。

```json
{"code": 200, "result": "Success", "message": "[\"……あ、来てくれたんだ。\", \"[[\\\"wait\\\",1]]\"]"}
```

HTTPのエラー、`result` が `Success` でない応答、`message` が行の配列でない応答は、失敗として扱います。応答が60秒返らない時も、結果が分からない失敗として扱います。

### 応答の行

1行が、シナリオの1つの発言です。

| 行 | 意味 |
|---|---|
| `[` で始まる行 | コマンドの配列（JSON）。例: `[["set","ruu",{"f":"ruu.svg","x":0.36,"y":0.33,"w":0.27,"h":0.48,"id":5}],["wait",1]]` |
| それ以外の行 | Roomの吹き出しに出す台詞 |
| データを返すactionの1行目 | データのJSON（`get_status` など、3・6節） |

読めない行（JSONとして読めない `[` の行や、コマンドの配列の形でない `[` の行）が1つでもあると、その応答は1行も実行しません。

XStoryBotのシナリオでは、発言の中の `{` `}` は変数の差し込みに使われます。コマンドの行のJSONは、`{{` `}}` と二重にして書きます（例: `[["set","messages",{{"visible":true}}]]`）。データのJSONは、`@set` で変数に作り、`{$変数!j}` で出力すると書きやすくなります。

LINEの窓口を持つBotでは、1回の応答は5行までです（ビルドの時に検査されます）。長い台本は、最後の行の `command` で続きを取り寄せます（[台本のコマンド](commands.md)）。

## 2. 画面を開いた時の流れ

1. Botとの接続を用意します。
   - LINE: LIFFを初期化します。LINEアプリの外で開かれ、`VITE_FORWARD_URL` があれば、そこへ移ります。ログインしていなければ、LINEログインへ進み、ログインした後は開いていたページへ戻ります。
   - Webchat: Webchatの画面（`VITE_WEBCHAT_ORIGIN`）と接続します。LINEのSDKは読み込みません。同じ枠で前のページが始めた操作が残っていると、Webchatの画面はそれが終わってから接続します（その間は読み込み中の表示のまま、操作と同じく60秒まで待ちます）。
2. `get_status` を送り、利用者の状態を受け取ります（3節）。受け取れなければ、エラーの画面を出します。
3. `event` に進行中のイベントがあれば、優先度の最も大きいイベントの台本を `<イベント名>:<ページ名>` で取り寄せます（4節）。取り寄せられなければ、イベントを読み飛ばしたまま進めず、台本を止めて知らせます（7節）。
4. 画像と書体（台本の台詞の文字を含む）の読み込みを待ってから、画面を表示します。台本の先頭の、表示前に実行できるコマンド（`set`・`set_hud`・`preload`・`disable_click_words`）は、表示の前に実行します。
5. 残りの台本を順に実行します。

## 3. `get_status`（利用者の状態）

応答の1行目に、JSONのオブジェクトを返します。

| 項目 | 内容 |
|---|---|
| `event` | 進行中のイベントと優先度。例: `{"intro": 10}`。空なら台本を取り寄せない。優先度が数でない時は、台本を止める（オブジェクトでない時は、下のとおりエラーの画面） |
| `lv` | ステータス表示のLv。返した値をそのまま表示する |
| `n_words` | ステータス表示のことばの数。返した値をそのまま表示する |
| `menu` | Roomの下に出すボタンのID（設定の `menu` の `id`）。無ければ、ボタンを出さない |
| `roomObjects` | Roomの物。名前 → 物のオブジェクト（[台本のコマンド](commands.md#roomの物)） |
| `words` | ことば帳。キー → 値（5節） |
| `missions` | ミッションの配列（5節） |

ここに無い項目を足してもかまいません。`set_hud` で書き換えられます。`roomObjects`・`words`・`event` がオブジェクトでない時、`missions` が配列でない時、物やことばの値が読めない時（物の `effect`、ことばの `w`・`s`・`f`・`onclick` が文字列でない、など）は、読めない状態のまま進めず、エラーの画面を出します（項目が無い時と `null` の時は、無いものとして扱います）。`set_hud` で書き換えた後の状態が読めない時は、台本を止めます。

## 4. イベントの台本とページ名

`event` に進行中のイベントがあると、画面を開いた時に `<イベント名>:<ページ名>` のactionを送ります。例えば、`event` が `{"intro": 10}` の時にRoomを開くと `intro:room` です。シナリオに応答の無いページでは、何も起きません。XStoryBotのLIFFのinterfaceで `ignore_unhandled_action: true` にすると、シナリオに無い `##liff.*` は空の応答になります（推奨）。既定の `false` では、シナリオに `##error_invalid_label` を書いていると、その応答が返ります。その応答に台詞があると、台詞を出せないページでは台本を止めます。

| ページ | URL | ページ名 |
|---|---|---|
| Room | `/` | `room` |
| ことば帳 | `/words/` | `words` |
| リンク集 | `/links/` | `links` |
| ミッション | `/missions/`（`?tab=cleared` で達成済みのタブ） | `missions` |
| 手紙 | `/messages/`（`?id=<id>` でその手紙を開く） | `messages` |
| 資料 | `/documents/<id>/`（`?route=<名前>` で崩れ方を選ぶ） | 資料のid |
| 作品固有のページ | `/<名前>/` | ページで決める |

台詞を出せるのは、Roomと、台詞の吹き出し（`MessageBubble`）を置いた作品固有のページだけです。ほかのページの台本に台詞があると、そこで台本を止めます（7節）。

## 5. 画面の操作から送るaction

| 操作 | 送るaction |
|---|---|
| Roomの物をタップ | 物の `onclick` |
| メニューのボタン | 設定の `action`（`href` なら移動、`send` ならトークへ送信） |
| ことば帳のことばをタップ | ことばの `onclick`。無ければ、表示の文字列をトークへ送って閉じる |
| 手紙を開く | 未読なら `on_message_read:<id>` を送り、受け付けられてから手紙の `onopen`。`onopen` は開くたびに送る |
| condition を満たす | condition の action |
| 台本の `command` | その action |

イベントの台本と同じく、応答の行を台本として実行します。台本の実行中に届いた応答は、実行中の台本の後ろに続けます。

物のタップ、メニューの `action`、ことばの `onclick` は、台本の実行中（台詞の表示中を含む）と、前の操作の応答を待つ間は受け付けません。二度押しで同じactionを重ねて送ったり、Botが処理した順と画面の台本の順がずれたりしないためです。送れなかった時は、何も起きません（もう一度押せます）。

ことば帳と手紙のページには、台詞を出す場所がありません。ことばの `onclick` と手紙の `onopen` の台本には台詞を書かず（書くと台本を止めます）、コマンド（`set`・`set_hud`・`go`・`send_chat` など）で応えてください。

### ことば帳の値

`words` の値は、`1` などの値か、次の項目を持つオブジェクトです。

| 項目 | 内容 |
|---|---|
| `w` | 表示する文字列。省略するとキー |
| `s` | 並べる時の読み。省略するとキー。「■」で始まる語は末尾に並べ、見出しは「■」の画像になる |
| `f` | 文字の代わりに表示する画像（`<dataDir>/words/` のファイル名） |
| `fade` | `set` で画像を差し替える時の、クロスフェードの秒数 |
| `onclick` | タップした時に、トークへ送る代わりに実行するaction |

見出しは読みの最初の文字で決まります（あ・か・さ…の行、英数字、その他、■）。

### ミッション

| 項目 | 内容 |
|---|---|
| `id` | ID |
| `img1` | 進行中の画像（`<dataDir>/missions/current/`） |
| `img2` | 達成後の画像（`<dataDir>/missions/cleared/`） |
| `cleared` | 達成したか |

## 6. データを返すaction

いずれも、応答の1行目にデータを返します。

| action | 応答の1行目 |
|---|---|
| `get_messages` | 手紙の配列。`{"id", "from", "title", "read", "sort", "content", "onopen"}`。`id` と `content` は文字列で必須。`read` が無ければ未読。`sort` の大きい順に並べる |
| `message_content:<content>` | 手紙の本文のHTML。`content` は英数字と `_` `-` `.` だけで書く（ほかの文字があると、本文を取り寄せない） |
| `on_message_read:<id>` | 何も返さなくてよい。既読のフラグを立てる |

手紙の本文からは、スクリプトを動かせるもの（`script` 要素、`on` で始まる属性、`javascript:` のURLなど）を取り除いて表示します。

## 7. 不具合の時に止める

物語の進行に関わる不具合では、台本を先へ進めずに止めます。まだ開いていないイベントへ、誤って進めないためです。

- このページで受け付けないコマンド（書き誤りや、Room用の `condition` をほかのページで使った時）
- コマンドの引数の誤り（行き先の無い `go`、秒数を読めない `wait`、対象の物が無い condition など）
- ページを開いた時のイベントの台本を取り寄せられない
- `command` の台本を取り寄せられない
- condition を満たしたことをBotへ伝えられない
- 手紙の既読をBotへ伝えられない（手紙の `onopen` を実行しない）
- 台詞を出せないページの台詞

止めた時は、残りの台本を捨て、Botの状態を進めるactionを送りません。止める前に送ったactionの応答が後から届いても、実行しません。利用者には「物語をうまく進められませんでした。時間をおいて、開き直してください。」と知らせます。開発中（`npm run dev`）は原因も表示します。直した後に開き直せば、最初から判定し直します。

ページのほかの操作は、止めた後も使えます。

## 8. 安全に使うために

- LIFFのactionは、利用者が自分で送ることもできます（LINEではアクセストークンを使って直接、Webchatでは自分のブラウザーから）。謎を解いた時のactionなどは、シナリオ側で前提のフラグを確かめてから受け付けてください（[サンプル](../../projects/demo/xstorybot/)の `jar_done` を参照）。
- 画面へ送ったデータは、利用者が読めます。まだ見せたくない語や画像の名前は送らないでください。
- 作品の `public/` に置いた画像は、名前を知っていれば誰でも開けます。物語の先の画像を先に置いても、秘密にはなりません。
- 画面は、Botへの送信を1つずつ、送る順に送ります（既読にしてから `onopen` を送る、など）。利用者の操作（物のタップなど）から送るactionは、台本の実行中と前の操作の応答を待つ間は受け付けません。
